# cell-lct / cell_su7 绘图实现对照

研究范围是原生对象生成、绘制顺序和恢复机制。不是调用其识别服务或采用其安装、计费、文案规则。

## 已读取的依据

- [cell-lct v0.2.1](https://github.com/yrui-cmd/cell-lct/tree/v0.2.1)：原版下载包中的 SKILL、README，以及本机适配版 `prepare_geometry_cache.py` / `cell_lct_cached_runtime.jsx`。本机适配版的上游识别器已改动，不能当作官方识别链路。
- [cell_su7 be84d36](https://github.com/yrui-cmd/cell_su7/tree/be84d36ed1b9e0657a7d6d6ca1f9769aec3dbed0)：`run_cell_ppt_ooxml.py`、`prepare_path_playback.py`、`run_ppt_path_playback.ps1` 及 PPT/Illustrator、白板诊断文档。结论对应该次源码读取；它不是这些项目的桌面实机验证。

## 原理比较

| 方面 | cell-lct | cell_su7 | 本 Skill 的 PowerPoint 分支 |
|---|---|---|---|
| 几何准备 | Master SVG 解析一次，保存锚点、控制点和 paint parts | 沿用几何缓存；PPT 写入原生 OOXML | 显式规则清单 + 复杂插画原生路径，编译一次 PPTX 缓存 |
| 可见过程 | Illustrator 按 20–50 atom 批次创建对象 | Windows PPT 先建对象，再改 Visible；Mac PPT 是文件生成 | Mac 在空白目标页逐批创建原生路径组，已实际观察中间态 |
| 复合路径 | compound 保留多个子轮廓 | 一个 DrawingML path 内保存全部轮廓；拒绝未处理的 even-odd | 子轮廓保存在同一个 custGeom path，未知或 even-odd 复合规则拒绝 |
| 顺序 | 缓存正序、背景到前景 | SVG 正序；Illustrator 集合反序 | 保留清单顺序；导出 Illustrator 集合时反序 |
| 恢复 | 稳定名称，跳过完成 atom/paint part | 保留缓存、平台会话和检查点 | 缓存哈希 + 实际目标对象名称/顺序前缀核对 |
| 性能 | 优化批次、连接与重绘，不减几何 | 原生文件生成避免大量 COM/剪贴板调用 | 用原生路径小组减少跨进程次数，默认无额外 delay；可见创建仍有传输成本 |

## 已吸收的约束

1. 复杂小鼠/细胞的可编辑性必须来自真实自由曲线；插入 SVG 图片不算。报告原生叶对象、路径组、文字和图片数，不能用组数替代内部路径数。
2. 一条复合路径中的内轮廓可以是洞。拆成各自填充的形状会产生白板等遮挡错误；移动到背后不能修复丢失的洞。保持子轮廓和绕向，不能用白色补片模拟一般镂空。
3. 不按大小或白色统一重排。跨层重复和透明叠加有语义，不能为提速盲删。只按明确区域清理经核对的旧文字/虚线碎片，保留记录。
4. 实时创建与逐个显示是两个不同模式。交付时描述实际采用的方式。这个 Mac 适配器已测试逐批创建；没有把 cell_su7 的 Windows Visible 循环称为 Mac 原生实现。
5. cell_su7 提醒重复剪贴板传输可能改变填色，因此本实现增加了保存前后填充/描边指纹核验，同时核验全部自由路径命令与控制点。实际测试中几何、填色、描边和文字指纹一致。
6. 调整批量大小和刷新节奏可以加速；减少路径、改变颜色、拆散复合路径不是传输优化。描摹本身仍是参考图的近似，缓存到目标的完整保留不能证明与原始位图逐像素一致。

## 本次 Mac 实测

PowerPoint 16.112.4，Illustrator 30.4.0 用于准备复杂插画矢量。原生结果包含 9,893 个叶对象、606 个路径播放组、32 个独立文本框，图片对象为 0。两只小鼠分别保留 864 / 852 条原生路径；清除了清单声明区域内的旧中性暗色连接器碎片。观察到了小鼠部分色块完成的两个状态，测试了暂停、单步和继续。保存后核对全部路径命令、控制点、填充/描边、对象顺序与文字，指纹一致，并检查 PowerPoint 导出的预览。

此结果仅证明本次 Mac 路线。Windows PowerPoint 的接口与性能需要独立实机验证。科学插画的一些结构仍采用示意性重建；不称为原图像素级复刻。
