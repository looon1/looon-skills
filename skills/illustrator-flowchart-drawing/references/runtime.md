# 运行与排错

## JSX 的执行入口

macOS Illustrator 可通过“文件 → 脚本 → 其它脚本”选择 JSX；本次验证的快捷键为 Command+F12。使用当前可用的应用自动化接口，不绕过工具的 UI 控制限制。

使用 CUA 时：

1. 选择实际 Illustrator App，读当前状态后打开脚本文件选择器。
2. 从最新可访问性树定位目标 JSX。在本次中文 macOS 文件选择器中，文件文本控件暴露的 `打开“访达”项目` 次级操作可直接执行选择；单击文件文字和连续快捷键曾无效。
3. 次级操作仅在当次状态明确暴露时使用。另一种方式是 Command+Shift+G，等前往路径表单出现后设置 `PathTextField`，确认选中文件，再点击“打开”。粘贴路径超时时可以对已观察到的文本控件使用 `setValue`。
4. 操作后读取新状态；不要跨窗口复用编号，不要把工具调用返回误认为脚本已经完成。通过任务日志确认 `DONE` 或 `ERROR`。实时阶段先返回 `READY`，这只代表控制面板就绪；点击开始后才逐批执行。

如果 JSX 日志长期没有进度，且应用没有错误日志，先检查真实前台与可见提示。 macOS 的保存步骤曾在 `aeInteractWithUser` 等待前台交互；先将 Illustrator 真正切到前台，不能把读取到窗口截图等同于应用已激活。保存和导出助手临时使用 `DONTDISPLAYALERTS`，并在 `finally` 中恢复原交互级别。不要反复排队提交脚本、强退 Illustrator 或丢弃未保存文档。每个标签完成后记录进度，便于定位具体文字。

## 已观察到的问题

| 症状 | 已验证处理 | 不应推出的结论 |
| --- | --- | --- |
| `Unable to set placed item's file`、`[UNKN]` | 使用独立 TIFF，通过 `app.open()` 取得 `RasterItem` 再调用 `trace()` | 没有证据证明所有 PNG 都不支持，也没有证据认定 ICC 就是根因 |
| 文档连接器返回无会话 | 检查本机 Illustrator；本次仍可通过原生脚本操作 | 不等于 Illustrator 不可用 |
| `≥` 变成方框或乱码 | 用 ASCII JSX 中的 `\u2265`，重新导出并重新打开 AI 核查 | 不要只看日志编码，也不要把符号改成不等价文字 |
| SVG 大到数十 MB | `fontSubsetting = SVGFontSubsetting.GLYPHSUSED` | 不需要为了缩小体积把主 AI 的文字全部转曲 |
| 导出后 `fullName` 指向 SVG | 保持明确 AI 路径，重新打开该 AI 核验 | 当前窗口标题不能代替磁盘文件回读 |

## TIFF 与颜色

准备脚本针对不透明 RGB 图像，将同样的 RGB 样本写入一个新的、不带原图 ICC 的 TIFF，并验证解码像素完全相等。源图文件保持不动。像素值相等不保证不同色彩管理设置下视觉颜色完全相同；若参考图依赖特殊配置文件，应在 Illustrator 中检查色彩管理，或采用保留配置文件的单独导入路线。

帮助脚本不自动处理透明、CMYK 或多页文件。遇到这类输入，先选择符合用户目标的导入或转换方式，不要默默合并透明度或更改颜色空间。

## 验证边界

原始实例在 Illustrator 29.5.1 中得到 26 处活文字、12 个插画组、1,220 条路径，位图和置入图像均为 0，并检查了 `≥` 的码位 8805。这是一次实际结果，不是新任务应当满足的固定数量。

整理为通用脚本后，2026-09-08 在同版本 macOS Illustrator 中再次完成重建与回读。实时入口分批重建了 1,246 个叶对象（1,220 条路径和 26 个文字对象）；原生导出的实时稿 PNG 与重建稿 PNG 像素完全一致。该旧测试只验证最终结果，未证明用户能看见绘制中间状态。Windows COM 启动入口仍需要 Windows 实机验证。

同日对插画内标签继续检查并补齐后，最终实例含 40 个原生 TextFrame、12 个插画组、1,197 条路径、零位图；实时创建 1,237 个叶对象，重建稿与实时稿 PNG 仍像素一致。下标使用普通数字文本框按下标位置排版，避免当前字体缺少 Unicode 下标字形。文字背景自动取色排除深色墨迹，修复了紧密小字错误选中黑色的情况。

上述下标拆分方式仅为旧测试记录。按 2026-09-17 整合的要求，数学/化学脚标必须使用正规结构化排版，不再沿用数字文本框拼接。公式允许正规排版后转矢量轮廓并保留源码，普通文字仍为真实粗体的原生文本框。执行与验收见 [公式排版与高保真验收](formulas-fidelity.md)；历史测试结果不证明新公式链路；2026-09-17 新版链路的独立测试见 [验证记录](validation.md)。

通用脚本采用上述已验证机制，增加输入、文件存在性和文档状态检查。每次使用仍须在实际 Illustrator 中运行并验收。

Adobe 官方说明：[编辑描摹结果](https://helpx.adobe.com/illustrator/desktop/manage-objects/traces-mockups-symbols/edit-image-trace-results.html)、[图像描摹面板选项](https://helpx.adobe.com/uk/illustrator/desktop/manage-objects/traces-mockups-symbols/image-trace-panel-options.html)。脚本接口细节优先检查实际安装版本的脚本字典和对象反射。

## 实时绘制的后续修正

2026-09-09 的检查确认旧版最终 PNG 一致不能证明中途可见。连续自发 BridgeTalk 消息在大图中仍使界面检查超时；当前实现由 Mac AppleScript 或 Windows COM 启动器分批调用，在 Illustrator 进程外等待 500 ms。原生结构与文本在第一批完整创建，后续复杂插画每批最多 8 项操作。文本保留逐字符字体与基线属性。创建分组后优先使用本批的对象引用，避免 Illustrator 集合缓存尚未更新时 `getByName()` 找不到新分组。

批次文件也必须把非 ASCII 字符转换为 `\uXXXX` 转义。原生文件入口曾将 UTF-8 批次中的 α、β、ϕ 错误解码；同一批次内的文字与清单一起乱码，计数与内容比较仍会假通过。因此保存回读要使用独立生成的 ASCII 清单，并实际检查导出字形。

验收必须包含真实空白画布、两个不同完成度的画布、暂停后进度稳定、单步只前进一批、继续完成、保存后回读及导出比较。Windows 仍需实机测试。

本次 Mac 实测完成 468 批、3,674 条路径、45 个 TextFrame、18 个插画组，位图及置入对象均为 0。暂停在第 30 批稳定超过 70 秒，单步只到第 31 批，继续成功；修正编码后的完整复测也观察到多个不同完成度的画布。独立清单回读通过，α、β、ϕ 字体与内容正确。完成时与重新打开后的 PNG 逐像素相等；相对于预先核验的矢量基准稿，3,362,526 像素中有 167 个边缘像素差异，未把它表述为原始参考图像素完全一致。

不要在同路径测试文档仍打开时从文件系统移走成品再覆盖该路径。Illustrator 可能保留旧实例，使 `app.open()` 返回旧内容。回读前应核对所有同路径实例；任一实例有未保存更改就停止，由任务上下文决定如何处理，不能自动丢弃。当前 `openClean()` 先检查全部匹配文档，再关闭已保存实例后重新打开磁盘文件。

## 原生几何与复杂插画分开播放

边框必须用四锚点矩形描边，虚线用 `strokeDashes`，箭头用少量锚点的描边路径和头部分组；不要沿用这些简单元素的描摹色块。清单中的 `nativeLayout` 声明原生元素并圈定需要保留的复杂插画。已有可编辑 AI 可以复制到新任务，执行 `structure` 重组，而无需再次描摹和恢复文字。分批捕获同时保留描边宽度、端点、连接和虚线属性。

本机曾忽略 `GradientColor` 的角度或矩阵赋值；对原生背景路径使用 `rotate(angle, false, false, true, false, Transformation.CENTER)` 只旋转填充渐变，并核对对象边界没有改变。大批变更后先 `app.redraw()` 再导出，避免尚未刷新的文字在 PNG 中缺失。

复杂源稿的播放准备曾超过 AppleScript 默认超时，但 Illustrator 随后仍写出 `READY`。Mac 启动器现为原生调用设置 240 秒超时。遇到超时先检查 `live.log`、游标与控制面板，不要立即排队重复提交；已有同一任务的就绪面板时，入口会复用该控制器。

2026-09-10 的机制图测试：首批创建 72 条路径和 45 个 TextFrame，复杂插画路径为零，红蓝框均为四锚点矩形，虚线为原生描边。随后共 284 批完成试播；暂停在第 151 批稳定 34.9 秒，单步只到第 152 批。放大检查后清除了混入复杂分组的 3 处旧箭头及 16 个虚线碎片，并把清理范围写回任务清单。以更新清单从源 AI 重新执行 structure，预览与清理后的基准稿逐像素一致。最终回读为 2,290 条路径、45 个 TextFrame、20 个插画组、34 项原生几何声明、零位图；19 处残片检查均为零。最终实时稿与重新打开后的 PNG 逐像素一致，与修正后基准稿有 137 个边缘像素差异；不代表与原始参考图片像素一致。

## 2026-09-17 新运行时

当前实现已加入正规数学排版、真实字体文件检查、复合路径/剪切组保留及可恢复批次。上文按日期保存的旧缺陷与测试不能覆盖当前状态；以 [验证记录](validation.md) 和本次任务实际日志为准。

本次实际修正的接口问题：

- Illustrator 29.5.1 的 `TextFrame.anchor` 赋值未实现，旋转后用 `translate` 校准基线，读回 anchor 验证。
- ExtendScript 没有可依赖的内置 JSON 对象；几何清单使用明确的 ASCII 转义读写，避免 Unicode 解码错误。
- 函数 `toSource()` 在该运行时可能丢弃换行，与注释组合会产生无效批次。现在批次小入口调用完整编译的 `batch.jsx`。
- 只有真正剪切组设置 `clipped=true`，不对没有剪切路径的普通组强设 false。
- TeX 使用 XeLaTeX XDV 直接转 SVG，避开 PDF 转换对 Ghostscript/mutool 的额外依赖。字体缺字明确失败。
- 描摹预览先导出、清除选区，再保存 trace.ai，避免预览导出后的脏标记阻止下一阶段。
- PNG 由已保存并重新打开的 AI 导出。旋转文字源稿→播放可能有少量边缘渲染差异，须记录；这不自动判为原图保真通过。
- SVG 回读可能将多行 text 拆为多个可编辑 TextFrame，因此比较文本行内容，而不要求它与原生 AI 的文本框数相同。
- `verify` 在入口拒绝关闭有未保存修改的同路径文档。阶段自身只读回并导出，结束时重新打开该已保存 AI，清除导出引起的应用脏标记，不丢弃用户在阶段开始前的修改。

`export` 只接受属于当前输出目录的活动文件。编译脚本、输入清单与 live 缓存必须对应同一指纹；不直接修改进行中的批次 JSON 或假造游标。
